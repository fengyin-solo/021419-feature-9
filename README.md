# MD Live Editor

一个基于 Vue 3 + CodeMirror 6 的 Markdown 即时渲染编辑器。实现类似 Typora 的所见即所得编辑体验——光标所在区域显示语法标记，离开后自动渲染为格式化效果，切换过程平滑无割裂。

## How to Run

### Docker 方式（推荐）

```bash
docker-compose up --build -d
```

### 本地开发

```bash
cd frontend-editor
npm install
npm run dev
```

## 图片插入说明

点击工具栏「图片」按钮可打开图片对话框：

- **选中文本后打开**：选中的文本会原样保留为「替代文本」，不会丢失
- **仅放置光标后打开**：在光标位置插入图片，正文其余内容不变
- **光标位于已有图片内再打开**：进入编辑模式，可修改替代文本 / 地址，替换的是原图片本身
- 对话框内提供实时预览（加载中 / 成功 / 失败 / 超时 / 本地路径 / 未知协议），失败与超时可直接重试
- 点击「取消」或按 Esc 不写入任何内容；确认前文档零变化

### 支持的图片格式

编辑器支持标准 Markdown 图片语法：`![替代文本](图片地址)`，也兼容尖括号地址与可选标题：
`![替代文本](<图片 地址.png> "标题")`

### 图片地址类型与渲染状态

| 状态 | 触发条件 | 是否可恢复 |
|------|----------|-----------|
| 加载中 | 地址已发起加载，显示转圈与目标地址 | — |
| 加载成功 | 图片正常显示，下方附替代文本 | — |
| 加载失败 | 地址不可达 / 非图片资源 / 未知地址 | 点击「重试」重新加载 |
| 加载超时 | 10 秒内未完成加载 | 点击「重试」，重试仍对应同一地址 |
| 未指定地址 | `![alt]()` 地址为空 | 点击「图片」按钮补全 |
| 本地路径 | `C:\…`、`\\host\…`、`file://…`、`~/…` | 改地址后预览与正文自动同步 |
| 未知协议 | `javascript:`、`ftp:` 等浏览器不加载的协议 | 编辑器不会发起请求，改地址即可 |

所有状态都只是**视觉层占位**，底层 Markdown 原文始终保留；把光标移到图片所在行即可回到原始语法编辑。

1. **网络图片（推荐）**
   - HTTP/HTTPS 地址：`![示例](https://example.com/image.png)`
   - 协议相对地址：`![示例](//example.com/image.png)`
   - data: 内联图片：`![示例](data:image/png;base64,...)`

2. **相对地址（会尝试加载）**
   - 站点绝对路径：`![图片](/images/photo.jpg)`
   - 相对路径：`![图片](./images/photo.jpg)`、`![图片](../images/photo.jpg)`
   - 裸文件名：`![图片](photo.jpg)`
   - 这类地址会按当前页面 URL 解析；若服务器上不存在对应资源，会显示可重试的失败状态，不会改动正文

3. **本地文件系统路径（浏览器无法访问）**
   - ❌ Windows 路径：`![图片](C:\Users\username\image.png)`
   - ❌ UNC 路径：`![图片](\\server\share\image.png)`
   - ❌ file 协议：`![图片](file:///Users/username/image.png)`
   - ❌ 用户目录：`![图片](~/Pictures/image.png)`

### 为什么本地路径无法显示？

出于安全考虑，现代浏览器禁止网页直接访问用户本地文件系统。即使输入了正确的本地路径，浏览器也会拒绝加载图片。编辑器识别这类地址后不会发起请求，而是给出可识别的警告卡片。

### 解决方案

1. **上传到图床**：将图片上传到图床服务（如 imgur、SM.MS 等），使用返回的网络地址
2. **本地服务器**：使用本地 HTTP 服务器托管图片，通过 `http://localhost:port/image.png` 访问
3. **Base64 编码**：将小图片转换为 `data:image/...;base64,...` 编码嵌入（不推荐大图片）

### 常见错误示例

```markdown
# 错误：语法颠倒（方括号应放替代文本，圆括号应放地址）
![C:\Users\benzhi\Desktop\BenZhiTec](错误示范)
# 正确语法：
![错误示范](C:\Users\benzhi\Desktop\BenZhiTec)
# 但即使语法正确，本地路径仍然无法在浏览器中显示

# 正确：使用网络图片
![错误示范](https://example.com/error-demo.png)
```

### 错误提示说明

- **「浏览器无法访问本地路径」**：输入了 Windows / UNC / file:/~/ 本地路径，浏览器安全策略禁止访问
- **「不支持的图片地址协议」**：使用了未知协议（如 `javascript:`、`ftp:`），编辑器不会发起请求
- **「图片加载超时」**：10 秒内未加载完成，可点击重试
- **「图片加载失败」**：网络图片地址无效或无法访问，可点击重试
- **「未指定图片地址」**：图片语法中缺少 URL 部分


## 题目内容

开发一个 Markdown 即时渲染编辑器，核心功能：

- 用户能够无损编辑 Markdown 文件并看到渲染效果
- 当光标所在区域存在语法标记时，展示语法标记（编辑模式）
- 当光标离开时，展示渲染效果（预览模式）
- 语法标记和渲染效果切换过程中，用户体验不能割裂
- 非双列模式，即时渲染

### 技术实现

- 基于 CodeMirror 6 的 Decoration 系统实现行内渲染
- 通过 ViewPlugin 监听光标位置，动态切换语法标记的显示/隐藏
- CSS transition 实现平滑过渡动画
- 底层始终保持原始 Markdown 文本，渲染仅是视觉层装饰
